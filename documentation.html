1. Abstract

SignalMarket is a decentralized application (DApp) built on the Ethereum Sepolia testnet that enables the buying and selling of sports betting market-making signals using the course-provided Yoda ERC-20 token.

The marketplace addresses a real-world use case: sports bettors who use quantitative models to identify positive expected value (+EV) opportunities can monetize their signals by listing them as on-chain assets. Each signal contains a public preview hint (sport, market type, edge percentage) and a hidden description (full pick details, closing line value data) that is only revealed to the buyer after purchase.

The project's signal data is sourced from ProphetX, a real sports analytics platform, using historical Closing Line Value (CLV) data from settled winning bets. This provides authentic, data-driven content rather than synthetic test data.

Key design decisions:

  • Zero external Solidity dependencies — the ERC-20 interface is defined inline so the contract can be pasted directly into Remix IDE with no imports or package managers.
  • Single-file frontend — pure HTML/CSS/JavaScript with ethers.js v5 loaded from CDN. No React, no build tools, no node_modules required to run the UI.
  • Token-gated content — signal descriptions are masked at the view layer, demonstrating the concept of ownership-based access control on a public blockchain.
  • Bloomberg terminal aesthetic — the frontend is styled as a quant trading terminal with a dark theme, monospace fonts, and real-time data presentation.

2. System Architecture

3. Smart Contract Design

3.1 Overview

SignalMarket.sol is a zero-dependency Solidity contract that implements a marketplace for signal assets. The ERC-20 interface (IERC20) is defined inline to eliminate any need for OpenZeppelin imports, allowing the contract to be pasted directly into Remix IDE.

3.2 Data Structures

Signal Struct

struct Signal {
    uint id;              // Auto-incrementing identifier
    string sport;         // "NBA", "MLB", etc.
    string market;        // "Player Props - Points", "Run Line", etc.
    string description;   // Full pick data (hidden until purchased)
    string previewHint;   // Public teaser with EV percentage
    uint priceInYoda;     // Whole-number price (e.g., 100 = 100 YODA)
    bool sold;            // Whether the signal has been purchased
    address currentOwner; // Deployer initially, then the buyer
}

3.5 Key Design Decisions

  • 18-decimal math: buySignal multiplies priceInYoda by 1e18 to match the Yoda token's 18 decimal places. Signal prices are stored as whole numbers for readability.
  • Approval pattern: Uses the standard ERC-20 approve + transferFrom pattern. Buyers must approve the SignalMarket contract to spend their YODA before purchasing.
  • Owner restriction: The contract owner cannot buy their own signals (require(msg.sender != owner)), preventing self-dealing.
  • View-layer masking: Description masking happens in getSignal and getAllSignals — the full data is always stored on-chain. This is a demonstration of access control, not encryption.

4. Frontend Application

4.1 Overview

The frontend is a single self-contained HTML file (frontend/index.html) with no build step. It loads ethers.js v5 from a CDN and communicates directly with the deployed smart contracts via MetaMask.

4.2 Design Aesthetic

The UI follows a quantitative trading terminal design language inspired by Bloomberg Terminal and similar financial data platforms:

  • Dark theme: Background #080B0F, surface #0D1117
  • Accent color: #00D4AA (teal/green for positive signals)
  • Typography: JetBrains Mono for data, Inter for UI text
  • Layout: Data-dense grid with minimal whitespace

4.4 Buy Flow

When a buyer clicks the Buy button on a signal card:

  1. The frontend converts priceInYoda to base units (price * 10^18)
  2. Checks the buyer's YODA balance is sufficient
  3. Reads current allowance(buyer, signalMarket)
  4. If allowance is insufficient, sends an approve transaction and waits for confirmation
  5. Sends buySignal(signalId) and waits for confirmation
  6. Refreshes balance, marketplace grid, and "My Signals" section

4.5 Wallet Integration

The DApp enforces Sepolia network selection. If the user is on the wrong chain, it calls wallet_switchEthereumChain and falls back to wallet_addEthereumChain if Sepolia is not configured in MetaMask.

5. Deployment Guide

Step 1: Prerequisites

  • MetaMask browser extension installed and configured
  • A Sepolia testnet account with ETH (from a faucet)
  • The Yoda ERC-20 token address (provided by course staff)

Step 2: Deploy SignalMarket.sol via Remix

  1. Navigate to https://remix.ethereum.org
  2. Create a new file named SignalMarket.sol
  3. Paste the entire contents of SignalMarket.sol from the project repository
  4. Open the Solidity Compiler tab:
    • Select compiler version 0.8.x (any 0.8 version works)
    • Click Compile SignalMarket.sol
  5. Open the Deploy & Run Transactions tab:
    • Environment: Injected Provider - MetaMask
    • Ensure MetaMask is connected to Sepolia
    • Contract: SignalMarket
    • Constructor argument _yodaToken: paste the Yoda token address
    • Click Deploy and confirm the transaction in MetaMask
  6. Copy the deployed contract address from the Remix console

Step 3: Configure the Frontend

Open frontend/index.html and update the two constants at the top of the script:

const YODA_TOKEN_ADDRESS = "0xbd27d0b7F9fedb5A2A2C3ceF5dC9c70f3CF64Af2";
const SIGNAL_MARKET_ADDRESS = "0x5D6Ec77a95Cc0A7EA6047faE8140F9128E397f73";

Step 4: List Signals (Optional — Automated)

  1. Create a .env file with your deployer private key: PRIVATE_KEY=your_key_here
  2. Run npm install to install dependencies (ethers, dotenv, csv-parse)
  3. Place your ProphetX transactions.csv in the project root
  4. Run: node scripts/listSignals.js --dry-run to preview
  5. Run: node scripts/listSignals.js to list signals on-chain

6. How to Run

Running the Frontend

cd frontend
python3 -m http.server 8080

Then open http://localhost:8080 in a browser with MetaMask installed.

Running the Scripts

# List signals (owner only)
node scripts/listSignals.js

# Fund a buyer wallet with YODA tokens
node scripts/fundBuyer.js

# Buy a specific signal as the buyer
node scripts/buySignal.js 3
Note: The .env file must contain PRIVATE_KEY (owner wallet) for listing and funding. For buying, it must also contain BUYER_PRIVATE_KEY and BUYER_ADDRESS.

7. Usage Guide

As the Owner (Seller)

  1. Click Connect Wallet — the DApp detects the owner and reveals the listing panel
  2. Fill in signal details: sport, market type, preview hint, full description, price in YODA
  3. Click List Signal and confirm the transaction in MetaMask
  4. The new signal appears in the marketplace grid

As a Buyer

  1. Click Connect Wallet and ensure you are on Sepolia
  2. Verify your YODA balance in the header bar
  3. Browse signals using sport tabs, search, market filter, or sort controls
  4. Click a signal card to view details in the modal
  5. Click Buy — the DApp handles approval and purchase automatically
  6. After confirmation, the signal description is unlocked and appears in "My Signals"
